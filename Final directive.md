# Final directive: Attendance Checker

This is the consolidated specification that drove the build, after two
rounds of design review on Day 1. It supersedes any looser statements in
`intent.md`. If this document and the code disagree, the code is wrong
and this document wins.

***

## 1. Scope (what is in / out)

**In scope.** A single local tool that:

* Reads one CSV of attendance and leave.
* Validates the CSV against a strict schema and surfaces every error
  with a row, column, and actionable message before any detection runs.
* Runs five deterministic anomaly detectors with configurable
  thresholds.
* Returns a flags table (one row per flag) with a neutral one-sentence
  explanation per flag and a pointer back to the source row.
* Renders the above through a Streamlit UI with a sidebar for the
  thresholds and a CSV download of the flags.
* Ships automated pytest coverage of schema, each detector, the
  pipeline, and edge cases.

**Explicitly out of scope.**

* Any form of machine learning, probabilistic scoring, or
  "misconduct" signal.
* Writing back to the source CSV or any mutation of input data.
* A weekly-hour-cap detector. Deferred to v2.
* Half-day leave as a first-class schema field. Deferred to v2;
  tolerated as a documented limitation in v1.
* Multi-timezone handling, holiday calendars, and database storage.

## 2. Non-negotiable principles

1. **Source data is read-only.** No detector or UI mutates the
   uploaded DataFrame. `ValidationResult` carries both the validated
   copy and a bitwise copy of the original.
2. **Validation and detection are separate.** Detectors assume a
   validated DataFrame and never silently coerce or skip rows. If
   validation fails, detection does not run.
3. **Thresholds are not hardcoded.** Every tunable number lives in
   `DetectionConfig`.
4. **Neutral language, always.** No flag code, reason string, or
   severity label uses the words `absent`, `absence`, `misconduct`,
   `fraud`, or `fraudulent`. Every reason ends in
   `record needs review` or `records need review`. One parametrized
   test enforces this across every detector output.
5. **All errors collected, not just the first.** A single call to
   `validate()` surfaces every schema error in the file.
6. **Reproducible sample data.** The demo CSV is generated by a
   seeded script; re-running produces byte-identical output.
7. **Honest logs.** `daily_log.md` records mistakes and fixes, not
   just successes.

## 3. CSV schema

One row per `(employee_id, date)`.

| Column | Type | Required | Validation |
|---|---|---|---|
| `employee_id` | string | yes | Non-empty, trimmed. Empty / whitespace-only is `EMPTY_EMPLOYEE_ID`. |
| `date` | ISO 8601 `YYYY-MM-DD` | yes | Strict `strptime("%Y-%m-%d")`. Anything else is `BAD_DATE_FORMAT`. |
| `scheduled_hours` | float in `[0, 24]` | yes | Non-numeric -> `NON_NUMERIC_HOURS`; negative -> `NEGATIVE_HOURS`; `> 24` -> `HOURS_OUT_OF_RANGE`. |
| `worked_hours` | float in `[0, 24]` | yes | Same validators as `scheduled_hours`. |
| `leave_status` | enum, nullable | no | Case-insensitive, trimmed; empty = no leave. Allowed: `sick, vacation, unpaid, bereavement, other`. Anything else is `UNKNOWN_LEAVE_STATUS`. |
| `notes` | string | no | Free text, ignored by detection. |

**Warnings (never fail validation):**

* `UNUSUAL_DATE` - date is before 2000 or after today. The reviewer may
  be auditing historical data; we only warn.

## 4. The five anomalies (frozen)

Each detector returns a DataFrame with the columns
`[source_row_index, employee_id, date, anomaly_code, reason]` and
nothing else.

### 4.1 `UNRECORDED_ATTENDANCE`

* **Trigger:** `scheduled_hours > 0` AND `worked_hours == 0` AND
  `leave_status` is empty.
* **Reason:** "Scheduled day has zero recorded work hours and no
  leave entry; record needs review."
* Must NOT flag approved leave with zero hours (`leave_status` set).
* Must NOT flag unscheduled days (`scheduled_hours == 0`).

### 4.2 `CONTRADICTORY_LEAVE`

* **Trigger:** `leave_status` set AND `worked_hours > 0`.
* **Reason:** "Leave status is set but worked hours are greater than
  zero; record needs review."
* **Known limitation:** half-day leave with partial work also fires.
  Documented, tested, and pinned.

### 4.3 `DUPLICATE_RECORD`

* **Trigger:** `(employee_id, date)` group size > 1.
* **Behavior:** flag EVERY row in the group; never deduplicate or
  drop. The reviewer decides what to do.
* **Reason:** "Employee has more than one row for this date (group
  size N); records need review." (N is the actual group size.)

### 4.4 `IMPLAUSIBLE_HOURS`

* **Trigger:** `worked_hours > config.max_plausible_hours`. Strict
  greater-than; equality does NOT flag.
* **Reason:** "Worked hours (H) exceed the configured plausible
  maximum (MAX); record needs review."
* Schema already rejects `< 0` and `> 24`, so this detector only
  deals with the configurable upper bound.
* 17-hour days must pass the schema and be available for this
  detector to flag.

### 4.5 `SUSTAINED_OVERTIME`

* **Scheduled-workday sequence (per employee).** The subset of rows
  where `scheduled_hours > 0` AND `leave_status` is empty, sorted by
  date ascending.
* **Over day.** `worked_hours - scheduled_hours >= overtime_margin`.
* **Streak.** Maximal run of consecutive over entries in the
  sequence.
* **Flag.** Every row in any streak whose length is
  `>= overtime_streak`. One flag per row, so the UI shows every
  affected day.
* **Reason:** "Day is part of a N-workday streak where worked hours
  exceeded scheduled by at least MARGINh; schedule needs review."
  (Reason mentions the schedule, not the employee.)
* **Effect of each situation on a streak:**
  * Scheduled over day -> extends.
  * Scheduled under-threshold day -> breaks.
  * Unscheduled day (`scheduled_hours == 0`) -> skipped: neither
    extends nor breaks.
  * Leave day (`leave_status` set) -> skipped: neither extends nor
    breaks.
  * Missing date (no row) -> skipped: neither extends nor breaks.
* **Gap rule.** If `config.max_gap_days` is set (default `10`), two
  consecutive entries in the sequence that are STRICTLY more than
  `max_gap_days` calendar days apart break the streak. Exactly at
  the limit does NOT break. Set `max_gap_days = None` to disable
  gap-breaking entirely.

## 5. `DetectionConfig` (frozen defaults)

| Field | Default | Range | Rationale |
|---|---|---|---|
| `max_plausible_hours` | `16.0` | `(0, 24]` | Headroom for legitimate 12-hour healthcare shifts; still flags 17h+. |
| `overtime_margin` | `2.0` | `>= 0` | A single long day is normal; +2h is where "sustained" starts to matter. |
| `overtime_streak` | `5` | `>= 1` | One business week. |
| `max_gap_days` | `10` | `>= 1` or `None` | Covers short vacations without accidentally merging unrelated project crunches. |

Invalid values raise `ValueError` at construction time.

Public, stable:

* `attendance_checker.DetectionConfig`
* `attendance_checker.SchemaValidationError`
* `attendance_checker.ValidationIssue`
* `attendance_checker.ValidationResult`

* `attendance_checker.analyze_csv(path, config=None) -> AnalysisResult`
* `attendance_checker.detect_unrecorded_attendance(data, config)`
* `attendance_checker.detect_contradictory_leave(data, config)`
* `attendance_checker.detect_duplicate_record(data, config)`
* `attendance_checker.detect_implausible_hours(data, config)`
* `attendance_checker.detect_sustained_overtime(data, config)`

Every detector shares the signature
`(data: pd.DataFrame, config: DetectionConfig) -> pd.DataFrame`.

## 7. Testing requirements

* `pytest` with no plugins beyond stdlib + pandas + pytest.
* One parametrized test asserts no detector reason contains any of
  `{absent, absence, misconduct, fraud, fraudulent}` on any fixture.
* Each malformed-input class has one dedicated fixture under
  `tests/fixtures/malformed/` and one dedicated test.
* Each detector has (a) a dedicated fixture with hand-picked rows,
  (b) a parametrized shared contract test for empty input +
  immutability + no-flags-on-clean, and (c) at least one boundary /
  configurability test.
* One end-to-end test (`one_of_each.csv`) exercises the pipeline
  with exactly one instance of each anomaly.
* One smoke test runs the pipeline against the full
  `sample_data/attendance_sample.csv` and asserts the injected
  anomaly counts.

Target: all green. Current: `91 passed`.

## 9. Known limitations (shipped on purpose)

* **Half-day leave** fires `CONTRADICTORY_LEAVE`. Add a `half_day`
  column in v2.
* **Split shifts** stored as two daily rows fire `DUPLICATE_RECORD`.
  Aggregate upstream.
* **Timezones** are not modeled; one file is one timezone.
* **Holidays** are not modeled; use `scheduled_hours = 0`.
* **Weekly caps** are not detected. Deferred.
* **Dates** before 2000 or in the future warn but do not fail.
